# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Aetheria is a playable Tower Defense MVP: Vite + React + TypeScript, battle board on a plain `<canvas>`. No game engine. `README.md` covers gameplay and the extend-by-data checklist; this file covers internal wiring.

## Commands & environment

Scripts in `package.json`: `dev`, `build`, `typecheck`, `lint`. **No test framework** — don't reference `npm test`. Verify with `npm run typecheck` plus exercising the app in the browser preview. Environment is **Windows / PowerShell**; Vite dev server on port 5174 (auto-bumps if taken).

**Update the patch notes on every GitHub push.** Whenever you push (or the user asks you to push) to GitHub, first prepend a new entry to the `PATCH_NOTES` array in `src/ui/components/PatchNotes.tsx` (newest first) summarizing the user-facing changes in that push, dont miss a thing. This changelog is shown in-game via the 📝 Patch Notes button next to the ⚙️ Settings icon in the `TopBar`. Do this as part of the push, not as a separate step to be reminded about.

**Don't block on browser screenshots.** The Browser pane is often not displayed, so `computer` screenshots time out — that's expected, not a failure to chase. A clean `npm run typecheck` plus a `read_console_messages`/`preview_logs` error check is sufficient. To drive the app headlessly, `import('/src/...')` modules in the page and construct a `GameEngine` (private methods callable via `engine['name']`), or seed `localStorage['aetheria-td:state']` and reload.

## Architecture

Strict one-directional layering — `ui → application → domain`, with `engine` a self-contained sibling. Inner layers never import outer ones. See `README.md` for the file tree. Load-bearing boundaries:

**`domain/` is pure data + rules.** Catalogs (`units`, `enemies`, `levels`, `rarity`) are plain objects; adding content is a data edit, never an `engine`/`ui` code change. **Single source of truth is the rule that keeps displays from drifting**: when a number appears on more than one surface, route it through one shared helper rather than recomputing inline. `masteryStats(unit, tier, purchased)` (mastery-adjusted damage/attack-speed/range) feeds the engine's `towerStats`, stat panels, `masteryUpgradeDeltas` ("+N DMG" labels), and the placement-range preview; yields go through `masteryHarvest`, crit through `critChanceFor`/`critMultiplierFor`, in-stage upgrade prices through `masteryUpgradeCost`. Attack speed displays via `formatAttackSpeed` (fractional from mastery multipliers).

**Levels are multi-lane.** A `LevelDef` holds `lanes: LaneDef[]`, each with its own `pathTurns` **and** `waves`. `domain/levels.ts` authoring accepts single-lane shorthand (`path`+`waves`) or explicit `lanes`; `buildLevels`/`specLanes` normalize both. Lanes may run separately or **converge** (share a tail of turn cells → enemies merge, shared exit dedupes to one castle). The engine precomputes per-lane geometry (`GameEngine.lanes`); each `Enemy` has a `laneIndex`; wave `i` spawns every lane's `waves[i]` in parallel; `totalWaves` = longest lane. **Victory requires clearing the final wave across all lanes** — killing the boss doesn't end the stage.

**Wave authoring & set-piece lanes.** A `WaveDef` is groups of `{ enemyId, count, spacing?, delay? }`: `spacing` (default `DEFAULT_SPACING`) is the gap between spawns *within* a group; `delay` offsets a group from the **previous group's start** (groups overlap unless delayed past it) — see `buildSpawnQueue`. A lane may set `revealAtWave: N` to stay hidden (undrawn, non-blocking, non-spawning) until wave N begins, then its path *rolls out* (`LANE_REVEAL_TIME`, read via `laneRevealFraction`; the renderer unrolls only its new stretch, up to where it first joins a visible path, by unmasking a bake of the ground with the lane in, so it is the real path material from the first frame; when it lands that stretch is stamped onto the ground already showing rather than re-baking, since a fresh bake re-deals every speck of path detail) and its cells start blocking building. A boss spawning on such a lane gets a throne-**rise** (and only a hidden lane whose waves carry the boss draws it seated beforehand, so other stages can hide lanes for plain foes, e.g. the Sewers' cistern lane from wave 3): `Enemy.rise` (1→0 over `RISE_TIME`) freezes it in place and untargetable while the renderer lifts it `RISE_LIFT`px and blends its sprite seated→walking (the Throne Room king). Targeting `first`/`last` compare `remainingToExit` (cross-lane distance to base), not per-lane progress. Bosses live in `domain/enemies.ts` `BOSS_META` (one per level, id `boss<levelId>`); stats come from an escalating curve, but any `BossMeta` field (`health`/`speed`/`reward`/`damageToBase`/`radius`) overrides its default. Don't add units to stages on your own, unless asked.

**Endless mode lives in `domain/endless.ts`.** One `EndlessSpec` per chapter (map + foe pool with per-foe `fromWave`/`cost`/`weight`) builds an ordinary `LevelDef` (ids from 1000, resolved by `getBattleLevel`) marked by `LevelDef.endless` rules. The engine treats such a level as `totalWaves = Infinity`, rolls each wave on `startWave` via `generateEndlessWave` (growing budget, `EnemyGroup.healthMult` scaling, a boss every `ENDLESS_BOSS_EVERY` waves cycling the chapter's stage bosses in order, ×1.6 HP per lap), never wins, and adds `ENDLESS_BOSS_GEMS` to `engine.gemsEarned` per cleared boss wave — `GameScreen` banks those gems immediately and records the chapter's best in `GameState.endlessBest` at settle. Unlocked per chapter by `isEndlessUnlocked` (all its stages cleared); "End run" calls `engine.surrender()`.

**The engine is framework-agnostic and headless.** `new GameEngine(level, startingGold, masteryUpgrades?, rng?)` — injectable `rng` (default `Math.random`) makes crit deterministic. It exposes mutable public fields (`currency`, `enemies`, `towers`, `masteryEarned`, …) and intent methods (`placeUnit`, `upgradeTower`, `startWave`, `deployStats`), and imports no React. `renderer.ts` only *reads* an engine snapshot — no rules. **Damage is mixed-timing**: melee (Swordsman) and line-AoE (Spearman) apply instantly (the Blade adventurer splits each attack into two half-damage cuts: one instantly, then a `Tower.followUp` cut `BLADE_SECOND_HIT_DELAY` later, crit rolled per cut, matching its two-blade swing); arrows/bolts (Archer, Crossbow, Wizard gust) are homing `Projectile`s carrying pre-rolled damage applied *on impact*, dropping harmlessly if the target dies first. All damage funnels through `damageEnemy(enemy, amount, source?)` — the choke point for kill credit and engine-only on-hit effects (e.g. Gale Force knockback). It is also where per-enemy defences resolve, in order: dodge (`dodgeChance`), then **shield** (`EnemyDef.shieldHits` → `Enemy.shield`: each hit of any size is absorbed outright and costs one point, emitting a `block` fx and `shieldBlock`/`shieldBreak` sfx; a blocked hit returns `false` like a dodge), then resistances and ward. The Man-at-Arms (`cap_grunt`, 5 hits) is the first shielded foe; the renderer draws remaining points as pips over the health bar (`drawShieldPips`, collapsing to a pip and a count above 6, sized by `Enemy.shieldMax`), on the boss bar, and in the hover tooltip. **Rally** (`EnemyDef.rally`, the Sergeant-at-Arms `boss7` with 15 shield): `updateRally` in `updateEnemies` counts `rallyTimer` down; a rally holds the enemy still for `duration` while `rallyT` counts up, and at `at` of the way through every *other* living foe gains `shield` points (stacking, raising `shieldMax`). It emits `rally` fx (call, then blessing with the shielded targets) and `rallyCall`/`rallyShield` sfx; the renderer blends the sprite through `rallyPose(e)` (passed as `sit`, the banner snap as `flourish`, both quantized into the cache key). **Summon** (`EnemyDef.summon`, the Hound Master `boss8`) is built the same way. `updateSummon` holds the enemy still for `duration` while it blows its whistle (`houndWhistle` sfx). `at` of the way through, it spawns `count` foes of `enemyId` just behind it on its lane via `createEnemy` (the same factory wave spawns use), emitting a `summon` fx. The call counts toward the cycle, so it fires every `every` seconds. The sprite pose is `summonPose(e)`. `Shot`/`Burst`/`FloatingText`/`Puff` are cosmetic and self-decay.

**`GameScreen.tsx` is the only bridge between React and the engine.** It builds one `GameEngine` per level mount, drives it from a `requestAnimationFrame` loop, and copies engine fields into a React `Hud` snapshot each frame. Selection/hover live in refs so the loop reads fresh values without re-subscribing. Rewards bank **exactly once** at battle end via a `settledRef` guard — mastery EXP win *or* lose, gems only on first clear. A foe reaching its bestiary unlock (`enemyUnlockKills`) for the first time mid-battle (banked kills + `engine.enemyKills`) queues a **field note**: `FieldNoteTab` pops in at the board's side, and clicking it freezes the sim (`noteOpen`, like `paused`) under `FieldNotePage`, a single bookmark-less journal page that inks the entry in (≈2.4s cap, click/Space to finish, Esc/Enter to close); its text comes from `ui/foeNotes.ts`, shared with `JournalBestiary`. Fast-forward sub-steps `engine.update(dt)` N times per frame (never one oversized `dt`) to keep motion/range fidelity.

**Procedural sprites cross the engine↔UI boundary.** `engine/sprites.ts` draws each champion silhouette, dispatched by `drawUnitSprite(shape, …)` and gated by `hasSprite(shape)`. `renderer.ts` paints board tokens with it; `ui/components/UnitSprite.tsx` calls the *same* functions for cards/menus, falling back to emoji for shapes without a sprite. To add one: write a `drawX`, extend `hasSprite` + `drawUnitSprite` — it appears on the board and every card at once. Enemies have a parallel `drawEnemySprite(id, color, view, faceLeft, dist, sit?)`/`hasEnemySprite(id)`; ids without a sprite fall back to the disc+emoji token in `drawEnemies`. Sprite authoring rules (complete `back` views, `footLiftFor` for oversized foes) are in `ART_DIRECTION.md`.

**Every figure goes through the figure compositor (`engine/figure.ts`).** Sprite functions draw flat fills; `paintFigure(ctx, draw, style, cacheKey?)` shades, rim-lights, outlines and composites them once, caching by `cacheKey` (LRU). Menus use the same pass via `ui/portrait.ts`. Bodies are built from `engine/anatomy.ts` parts. Shading, cache and anatomy conventions are in `ART_DIRECTION.md`.

**Board frame pipeline (`renderer.ts` `drawBoard`).** Per-engine state (baked terrain, `Lighting`, `Vfx`, prop lights) lives in a `WeakMap` keyed by the engine. Passes: baked ground (`terrain.ts`: seeded floor material per `BoardTheme.floor` + path material per `BoardTheme.pathKind`, re-baked only when the set of fully revealed lanes changes; a lane mid-reveal is stroked live) → ground-layer props (`drawGroundProps`: the throne dais, the plaza mosaic, pigeons — before the placement hints and range rings, so those draw over them) → ground decals (`Vfx.drawDecals`: the Earthsplitter's cracks, under every figure) → depth-sorted world (props by `PROP_META.base`, champions, foes, corpses; tall `occludes` props fade to 50% when a figure stands behind) → normal-blend VFX → lighting (`lighting.ts`: half-res ambient darkness with lights punched out, additive glow, sun wash, soft-light grade) → glow pass (attacks, projectiles, additive VFX — never darkened) → vignette → unlit overlays (health bars, AoE guides, floaters, boss bars). Stage mood (darkness, light family, weather, grade, vignette, sun) is data in `domain/atmosphere.ts`: named `MOODS` presets a stage picks with `mood: '<name>'` in its `LevelSpec`, else the chapter's `SECTION_MOODS` default. **The engine emits cosmetic `fx` events** (`hit`/`kill`/`blast`/`cast`/`crossSlash`/`cleave`/`fissure`/`dodge`/`breach`/`deploy`/`bossSpawn`, the visual twin of `sfx`, capped at 400); `drawBoard` drains them into `Vfx`, which owns particles (pooled, 900 cap), rings, flashes, slash crescents, Cross Slash X marks, cleave arcs, fissures, light pulses, exposure lifts, hit recoil, corpses and screen shake (off under `prefers-reduced-motion`). Never read `fx` back in rules. Shared colours/easing/seeded RNG live in `engine/palette.ts` — pull ink, light families and materials from there rather than new hexes.

**Board dressing is cosmetic, but blocks placement.** Types in `domain/decor.ts`, drawing in `engine/props.ts`. A `BoardTheme` (checker colours = floor material tones, optional path stroke layers, `floor`/`pathKind` materials) and `DecorProp[]` come from level data `LevelDef.theme`/`.decor` (the castle stages ship both); a stage lacking `decor` data falls through to `drawLegacyDecor(levelId)`. Props render through the shared `drawProp` dispatch (same as the Level Designer palette/preview; re-exported from `renderer.ts`). Each kind has a `PROP_ART` entry (`origin` offset to its footprint centroid, `shadow`, cached `body` through the compositor with a quiet ink, animated `live` overlay for flames/water) and a `PROP_META` entry (draw `layer` ground/standing/overhead, `bounds`, `base` depth line, `occludes`, `lights`, `flames`, `chimneys`) — **when you redraw a prop, update its `bounds` too** (they size the compositor box and the occlusion test). Each also has a `PROP_FOOTPRINTS` cell footprint (multi-cell props anchor top-left). **Lightable props and mist** (`domain/mist.ts`): a `LIGHTABLE_PROPS` kind (the `lanternPost`, with a gold `cost` and a `radius`) starts dark. Clicking it in-stage calls `engine.lightLantern(decorIndex)`, which adds the index to `engine.litLanterns`. On a stage with `LevelDef.mist` (the Outskirts) every champion's range is multiplied by `MIST_RANGE_MULT` (0.7) unless its cell centre lies within a lit lantern's radius: `engine.mistRangeMult(col, row)` is the single source, folded into `Tower.range` in `recomputeRangeAuras` (stored as `Tower.mistMult`, read by the stat panel and the "Lost in the Mist" entry) and into the placement preview. Light also works on foes: an `EnemyDef.lightSlow` foe (the Bloodhound, `cap_runner`) eases `Enemy.cower` up inside any lit lantern's radius (`updateCower`, measured from its position) and back down outside it, and its speed is blended toward `lightSlow` by it. A path may end on the board only on a **base prop** (`BASE_PROP_KINDS`: the castles, the gate, the sewer entrance, the escape wagon); the Level Designer checks this. **`canPlaceAt` forbids building on path cells *and* decor cells** — `GameEngine.decorCells` comes from `decorCellKeys(level.decor)`, or the `CASTLE_DECOR_CELLS` mirror table for decor-less stages (keep it in sync with `drawLegacyDecor`). Theme/decor/mood live on the stage's spec and legacy decor/boss are keyed by level **id**, so reordering a stage moves its room content, legacy decor case, `CASTLE_DECOR_CELLS` entry and `BOSS_META` entry together.

**Ending cutscenes.** A stage may close on a cutscene (`LevelDef.ending`, data in its `LevelSpec`; only The Getaway's `getaway` so far). When such a stage is won, `GameScreen` banks rewards as usual, holds a beat (`ending` goes `pending`, then `playing`, then `done`), then mounts `ui/components/GetawayCutscene.tsx`, passing the board canvas's on-screen rect as `from` so the cutscene zooms out from it. That is a portalled full-screen overlay with its own canvas and rAF loop; `GameScreen`'s loop skips drawing while it plays, and the result card waits until its `onDone`. When it ends or is skipped it calls `onDone` at once (the result card comes up beneath), fades the whole overlay out, letterbox and all, and then calls `onClosed` so `GameScreen` unmounts it (`cutsceneOpen`). Its two acts are engine-layer directors with no React:
- `engine/cutscene/getawayBoard.ts` animates the finished board through `RenderUiState.scene`, a `BoardScene` that hides the deployed champions (`hideTowers`) and chosen decor (`hiddenDecor`, its lights too), and adds depth-sorted lit `actors` and moving `lights`. Cosmetic only; it never steps the engine.
- `engine/cutscene/journey.ts` paints the side-scrolling ride.

Both push sound cues the component voices through `ui/cutsceneAudio.ts`, and the ride swaps in the `journey` music track. `GameScreen` claims its battle theme on mount, so a retry gets it back; it does not restore the theme on unmount, which would blip the battle theme on the way to the menus. The moving wagon is the parked prop's own painting (`paintWagon`, exported as `drawWagonRig`); champions are drawn with `championFigureStyle`, the board's finish. Art and audio details are in `ART_DIRECTION.md`.

**UI art language.** Fonts, CSS tokens (top of `ui/styles.css`), the inline-SVG `Icon` set (no emoji in UI chrome), the menu backdrop (the blurred `DeskBackdrop`) and the summon ceremony are described in `ART_DIRECTION.md`.

**Modals must `createPortal(…, document.body)`.** Each `.screen` (a fade-in transform) establishes a containing block that would clip a `position: fixed` overlay. `Settings`, `ChampionDetail`, `MasteryTree`, `LevelDesigner` portal out; `.modal-backdrop` is a scrollable top-aligned flex container. Direct children of `.app` are lifted over the `Backdrop` by a zero-specificity `.app > :where(:not(.backdrop))` rule — keep it `:where()`, or it overrides the fixed TopBar corner and the fixed journal overlay (`.intro-root`), which then renders below the page. Sheets opened from inside the journal (`ChampionDetail`, `MasteryTree`) are lifted over `.intro-root` by `body:has(.intro-root) > .modal-backdrop`. (The Level Designer, in Settings → Developer, previews the design through the real `drawBoard` on a throwaway `GameEngine` (level id -1, so no id-keyed theme/legacy decor applies). It can start from any existing stage or endless map, edits every path (tabs per lane; clicking onto another path merges into it, copying its route to the shared castle), props, floor/path materials and colours, previews any mood preset or chapter default via the optional `LevelDef.atmosphere` override, and exports a `path:`/`lanes:` (stage) or `paths:` (endless) plus `theme:`/`decor:`/`mood:` snippet to paste into a `LevelSpec` or `EndlessSpec`. New presets are authored in `MOODS` in `domain/atmosphere.ts`.)

**State + persistence go through the store.** `application/store.tsx` holds the single `GameState`, mirrors it in `stateRef`, and `commit()` persists every change through `infrastructure/storage.ts` (the sole `localStorage` point, namespaced `aetheria-td:`). UI reads state and calls actions via `useGame()`; it never touches storage or mutates state. Transitions in `gameState.ts` are pure. **Persistence is versioned**: bump `CURRENT_VERSION` and add a normalize line in `loadState` (e.g. `migrated.x = { ...(raw.x ?? {}) }`) whenever you add a `GameState` field.

**Teams gate deployment.** `GameState.team` is the ≤`MAX_TEAM_SIZE` (6) champions deployable in a stage; the in-stage deploy list reads `team`, not `ownedUnits`. Some mastery effects are *passive team bonuses* (e.g. Fresh Food starting gold via `masteryStartingGoldBonus`) applied from the roster without deploying.

**First-launch player intro & the custom avatar.** When there is no saved `GameState.player`, `App.tsx` renders `ui/components/PlayerIntro.tsx` in place of the normal shell — a journal cinematic + character-creation "Identification Page" where the player builds a portrait (`PlayerSpriteCreator`) and signs a name. `GameState.player` (a `PlayerProfile` = `{ name, sprite }`, `null` until finished) **is** the "intro completed" flag; `hasCompletedIntro(state)` gates it, so an existing (pre-`player`) save runs the intro once *without touching its progression*. The profile is committed **only at the very end** of the sequence (`onComplete` → `setPlayerProfile`); committing sooner would flip the gate and unmount the component mid-animation, so quitting halfway just replays the intro. The avatar is a **composed** sprite — unlike the monolithic champion `drawX` functions, `drawPlayerSprite(ctx, cfg, faceLeft)` in `engine/sprites.ts` assembles interchangeable parts from a `PlayerSpriteConfig` (`domain/playerSprite.ts`: build/skin/eyeColor/marking/hair/hairColor/facialHair/outfit/outfitColor/accentColor/headwear/headwearColor/cloak/cloakColor) yet obeys the same drawing conventions so it stands beside the champions. **Adding a part option** is a catalog entry in `playerSprite.ts` plus a branch in the matching `drawPlayer*` helper; a new *field* also needs its `SPRITE_CATEGORIES` row (with its creator tab `group` and tile `focus`), a default, a `randomPlayerSprite` line and a `normalizePlayerSprite` line (that line is the save migration). The creator (`PlayerSpriteCreator`) renders every option as a thumbnail tile through `PlayerSprite` (`framing` `full`/`snug`/`bust`, optional `weapon`). Journal ornaments (flourish, compass rose, page corners, wax seal, cover corners) are inline SVG in `ui/components/JournalArt.tsx`. **The journal is also the hub for champions and the bestiary** (there are no separate Champions/Bestiary screens). In review mode, three bookmarks (`JournalSection`: `profile` | `champions` | `bestiary`) switch between the adventurer's own pages, `JournalChampions` (team slots plus the roster, with `ChampionDetail`/`MasteryTree` opened from it) and `JournalBestiary`. `App` holds the open section in `journal` state; the home desk's journal opens it on `profile` and the campaign's Edit team on `champions`. The TopBar is not a bar: just gems, patch notes and settings floating in the top-right corner (`.screen` top padding clears them), with no navigation: the home desk's objects lead to each screen, and each of those screens has its own back button. The battle-profile numbers on both the journal plate and `ChampionDetail` come from `championStatTiles` in `ui/championStats.ts`. Persist the reconstructable config, never a rendered image; other systems redraw it via `ui/components/PlayerSprite.tsx` (`<PlayerSprite config={state.player.sprite} />`). `normalizePlayerSprite` repairs stored configs (colour fields accept any custom hex; unknown/removed part ids fall back to defaults), so it doubles as the migration when the catalog changes — `loadState` runs it via `normalizePlayerProfile` and a `null`/invalid result re-triggers the intro. Sound effects (`ui/introAudio.ts` and friends, all synthesized) and background music (`ui/music.ts`; `App` picks the track, `GameScreen` sets its intensity) are covered in `ART_DIRECTION.md`.

## Armor — the adventurer's equipment

**Armor is stat-boosting equipment exclusive to the player champion(s) — it is never drawn on the sprite, only shown as item icons — and lives in `domain/armor.ts` as pure data**: `ARMOR_SLOTS` (helmet/chest/legs/boots), `ARMOR_RARITIES` (colour, `statCount`, `dropWeight`, `salvageGems`), `ARMOR_STATS` (every rollable stat: label, pick `weight`, and a `[min, max]` range per rarity), `ARMOR_DROPS` (the endless-boss drop chance; campaign bosses never drop armor) and `ARMOR_SETS` (one per chapter via `section`, only Castle's `kingsguard` so far: piece names per slot, a 4-piece `setBonus`, an icon `style` + `cloth` colour). **Stats are rolled per piece**: `rollArmorStats` picks `statCount` different stats (2 for Common/Rare, 3 for Epic/Legendary) and values each uniformly in its rarity's range, so every owned piece is an individual `ArmorPiece` (`id`, set, slot, rarity, rolled `stats`); an `ArmorRoll` is the same without an id (drops, forges). `GameState.armor` holds `items`, `equipped` (slot → piece id) and `nextId`; `addArmor` assigns ids, `equipArmor`/`unequipArmor`, `salvageArmor(ids)` skips worn pieces, `equippedArmor(state)` resolves the worn pieces. `normalizeArmorPiece` keeps rolled values even if ranges are retuned; the v17→v18 migration re-rolls each counted v17 piece at its rarity, and the store saves right after loading so such random migrations don't re-roll on every load. **Armor is locked until the player champion learns its tree’s major node** (the `unlocksArmor` node in each `player-*` `MASTERY_TREES` entry, read via `masteryUnlocksArmor`/`armorUnlockNode`): `isArmorUnlocked(state)` gates it — the store passes no worn armor to `syncPlayerChampions` while locked or while the hero's mastery is switched off (`isArmorActive`, read from the *effective* mastery; equipping and drops still follow `isArmorUnlocked`), `GameScreen` sets `engine.armorUnlocked` (no boss drops while false), and the journal plate shows locked slots that open the skill tree instead of the Armor button. **Bonuses reach every surface by being baked into the def**: `syncPlayerChampions(profile, owned, equippedArmor(state))` runs `applyArmor`, which sets `UnitDef.gearBonus` (damage/attack-speed/range multipliers read by `masteryStats`, crit read by `critChanceFor`/`critMultiplierFor`), raises `maxMana`, and shortens the tier-3 ability's `cooldown`. Drops roll in the engine: `damageEnemy` calls `rollArmorDrop(level.section, endless, rng)` on a boss kill (null outside endless) and pushes to `engine.armorDrops`; `GameScreen` banks new entries the moment they appear (like endless gems), shows a toast and lists them on the result card. The `Armory` modal (from the journal plate's **Armor** button or `ChampionDetail`) is the equip screen. The Developer menu (Settings → Developer, `Developer.tsx`, a grid of tool cards) has an **Armor forge** (pick set/slot/rarity and roll pieces via `rollArmorPiece` → `awardArmor`) and a **Hero class** switch (`setPlayerChampionClass`: swaps the profile's proficiency and replaces the owned `player-*` champion and its team slot; mastery stays keyed per id, so switching back restores it).

## Two distinct upgrade systems — do not conflate

- **In-stage upgrades** (`UnitDef.upgrades`): bought with **gold**, live on the deployed `Tower`, **reset every stage**. Sequential tiers; combat reads the tower's `effectiveStats`/`effectiveGenerate` fields.
- **Mastery skill tree** (`MASTERY_TREES` in `domain/mastery.ts`): bought with **permanent EXP**, stored per-champion in `GameState.masteryUpgrades`, applied **every** stage. Nodes are pure data with typed effect fields (`damageMult`, `rangeMult`, `critChanceBonus`, `generateMult`, `startingGoldBonus`, `throwEvery`, `adjacentDamageMult`, `rangeAuraMult`, `preloadShots`, `knockback`, `upgradeDiscount`…). `requires` makes a **sequential** tree, omitting it makes **parallel** nodes; `major: true` is a cosmetic gold outline; `exclusiveGroup` makes several learned nodes mutually exclusive (only one active). EXP comes from kills (`expForKill`; brutes/bosses worth more) and Farmer gold (`GOLD_PER_EXP`), plus a win bonus for every `team` champion (deployed or not) of `stageClearExp(totalWaves)` (`STAGE_CLEAR_EXP_PER_WAVE` = 5 per wave; campaign stages only, endless never wins), all banked once per stage via `awardMastery` from `GameScreen`'s settle.

**Purchased vs. active vs. effective** — three resolutions in `gameState.ts`, don't confuse them: `masteryUpgradesFor` (everything learned; MasteryTree "learned" markers), `activeMasteryUpgradesFor` (learned minus non-selected exclusive members; the tree's active markers), and `effectiveMasteryUpgradesFor` (active, or `[]` when the champion's `masteryDisabled` switch is on). Every **effect** surface reads the effective list — the engine and passive bonuses via `resolvedMasteryUpgrades(state)`, the in-stage panel/stat sheet/card yields directly.

**Adding a mastery effect:** add an optional `MasteryUpgradeDef` field, aggregate it in a `mastery*` helper, and consume that helper everywhere the stat is used (engine + every display) — the single-source rule keeps menus, the in-stage panel, and the simulation in agreement. Most effects fold into `masteryStats` at deploy. Some are **dynamic**, living only in the engine because they depend on live board state: board-position auras (`adjacentDamageMult` Better Morale, `rangeAuraMult` Guiding Gale) recomputed in `recomputeAdjacency` on every place/sell/upgrade, `preloadShots` (Quick Loader) per-frame firing state, and `knockback` (Gale Force) applied in `damageEnemy` with a per-enemy cooldown — surfaced through mutable `Tower`/`Enemy` fields the renderer reads.

**Weapon forms re-arm a hero through its def, not the engine.** A node with `weaponForm` (the Blade's `claymore`, read via `masteryWeaponForm`) swaps the hero's whole kit. `playerChampionForms(state)` resolves each `player-*` id's form from its *effective* mastery, and the store passes that to `syncPlayerChampions`, so `buildPlayerChampionDef(id, …, form)` builds a different `UnitDef` under the **same id**: the Claymore is shape `player-claymore` with `aoe: 'cone'` + `coneAngle`, its own `upgrades` and the Earthsplitter ability. Every surface (deploy list, in-stage panel, ChampionDetail, the journal plate and Armory doll via `adventurerWeapon` in `ui/portrait.ts`) picks it up through `getUnit`. Mastery, ownership and team slot stay keyed by the id, and swapping the active node back restores the dual blades. In the engine a `player-claymore` cone charges `CLAYMORE_WINDUP_TIME` (the heft) and then resolves as an instant melee cleave (`fireCleave`), not the Wizard's travelling `fireCone`. The Bow has the same pair of rival paths (`bow_style`): **Fivefold Volley** (`burstShots` → `masteryBurst`, the volley size read by the engine's `Tower.burstCount` and every DPS/volley display) and the **Longbow** form (shape `player-longbow`, no burst): every shot charges `LONGBOW_DRAW_TIME` (the slow draw, capped to a share of the reload) and looses one big homing arrow from `fireLongbow`; its Piercing Shot ability nocks `charges` piercing arrows (`Tower.pierceShots`) that fly straight to the end of its range (`Projectile.pierce`, advanced by `advancePierce`), striking every foe they pass once. The Blade's other path, **Cross Slash** (`crossSlashEvery`/`crossSlashMult` → `Tower.crossSlash*`), lives in `fireBlade`: every Nth attack replaces the two half cuts with one X cut delivered as a `followUp` with `cross: true`. That blow lands `CROSS_SLASH_HIT_DELAY` in, and if its target fell meanwhile it retargets the nearest foe in reach. The Magic hero's rival paths (`magic_style`) are the **Arcane Staff** form (shape `player-staff`, `burst: 3`, its own Mana Storm ability): each cast charges `STAFF_CAST_TIME` (the raise) and `fireStaff` looses `burstCount` bolts from `STAFF_MUZZLE`, `STAFF_BOLT_STAGGER` apart (`seek.delay`), one per distinct foe in range (primary target first, then the targeting order; with fewer foes the spares cycle back over them). Each bolt is a `Projectile.seek` advanced by `advanceSeek`: launched in an upward fan, it coasts, then turns ever harder toward its foe while accelerating, and goes straight in after `STAFF_BOLT_LOCK`. And **Greater Orb**, which upgrades the existing kit rather than re-arming it: its node carries plain `damageMult`/`attackSpeedMult` plus `burstRadiusMult` (→ `masteryBurstRadius`, the single source for the engine's `Tower.burstRadius`, the blast preview and the radius displays) and the `greaterOrb` flag (→ `masteryGreaterOrb` → `Tower.greaterOrb`). The engine then charges `GREATER_ORB_CHARGE_TIME` (the leap; capped to a share of the reload), releases through `throwGreaterOrb` (the throw-down + landing play on `specialAnim`, the orb leaves from overhead at `GREATER_ORB_MUZZLE`, and with no foe left at release it still comes down on the last aim point), and detonates with a `heavy` blast. The leap/throw phases are the `GREATER_ORB_*` constants in `engine/types.ts`, shared by sprite, renderer and engine.

## Hero activated abilities & mana

**Heroes (the three `rarity: 'hero'` player champions) have activated abilities + a mana pool — a third system, distinct from the two above.** An ability is data (`AbilityDef` on a tier-3 `UpgradeDef.ability`; no stat deltas that tier): `effectiveAbility(unit, tier)` resolves it, `applyTierStats` grants it to the `Tower` once (so a hero auto-levelling in gains it mid-stage). The player fires it from an icon in the in-stage panel (`AbilityButton` in `GameScreen`, driven by an `AbilityHud` snapshot); casts go through `GameEngine.activateAbility(uid)` which switches on `ability.id` (`castCycloneSlash`/`castQuickdraw`/`castPiercingShot`/`castManaRay`/`castManaStorm`/`castEarthsplitter`). Each ability is gated by a cooldown (`Tower.abilityCooldown`, radial countdown on the icon), mana, **and** — for a damaging one (Cyclone Slash, Mana Ray, Mana Storm, Earthsplitter) — a foe within its reach (`abilityHasTarget`; the button just loses its ready gold and nothing is spent). Those casts aim at the live target if it is in reach, else the nearest foe that is (`abilityAim`). **Mana**: `UnitDef.maxMana` (all heroes = `HERO_BASE_MANA` 50) → `Tower.mana`/`maxMana` (starts full); casting spends `ability.manaCost`; it refills by landing killing blows — every `EnemyDef.mana` is added to the killing hero's pool in `damageEnemy` (capped) — plus passive `UnitDef.manaRegen` → `Tower.manaRegen` (per second, ticked in `updateTowers`; only from the armor stat Mana regen so far). Shown as the blue mana bar in the champion panel. Ability kinds so far: instant-AoE (Cyclone Slash — hits all in range), timed self-buff (Quickdraw — its own `abilitySpeedBuffMult`/`Timer` slot, **stacks** with the Bard's `attackSpeedBuffMult`, flares the player foot-outline), channelled beam (Mana Ray — `Tower.beam*` fields: locked angle/range at cast, suppresses normal attacks in `updateTowers`, ticks a line-AoE every `tickInterval`, drawn slim from the hands by `drawBeams`), channelled barrage (the Staff's Mana Storm — `Tower.storm` holds the channel for `duration`, suppressing normal attacks like the beam; `updateStorm` looses a bolt every `stormBoltEvery` (the normal bolt rate × `speedMult`) at a random foe in range, each a `Projectile.rain` advanced by `advanceRain` up and over onto its foe for `damageMult`× damage; the staff is hoisted over `MANA_STORM_RAISE`/lowered over `MANA_STORM_LOWER`, read through `manaStormStance`), and delayed fissure (the Claymore's Earthsplitter — `Tower.slam` locks aim/reach (`reachMult`)/damage at cast and strikes a line `aoeWidth` wide after `EARTHSPLITTER_HIT_DELAY`, shoving survivors back by `knockback`; no normal attacks until its `specialAnim` slam ends), and empowered shots (the Longbow's Piercing Shot — `AbilityDef.charges` arrows nocked into `Tower.pierceShots` after a short `specialAnim` cast pose; self-targeted, so no foe is needed to cast). Signature-move animations (Cross Slash, the Earthsplitter slam) run on `Tower.specialAnim` over `specialAnimTime(shape)`, separate from `attackAnim`. Ability icons are round medallion PNGs in `public/` (`cyclone_slash.png`/`quickdraw.png`/`mana_ray.png`/`earth_splitter.png`, transparent corners, own painted rim — the button adds no frame) with an emoji fallback on a plain disc (Mana Storm has no PNG yet, so it shows 🌠). The Earthsplitter telegraphs: a held wind-up (blade kindling, `drawSlamTelegraphs` glowing the crack's path) before the slam. In-stage stat panel recolours buffed stats by **category** (`.buff-spd/dmg/range/crit/dps`), not by source.
